# ToonAge — Development Rules & Style Guide
# Reference this file for coding standards and conventions.

## LUA STYLE
- Local references: `local TA = ToonAge; local U = TA.Utils`
- Module pattern: `local M = {}; TA:RegisterModule("Name", M)`
- Every module MUST have: `Init()` (optional), `OnEvent(event, ...)` (optional), `Render(content, sidebar)` (for UI tabs)
- Use `pcall` for any Blizzard API call that might taint or error
- Use `U.SafeNum(val)` for any potentially tainted number from WoW API
- File-scope constants: ALL_CAPS with underscores
- Comments: `-- Single line` for inline, `-- ══════` section separators for major blocks
- Clean up frames: every Render() must hide/nil old frames before creating new ones
- Frame pool: reuse frames via the pool pattern in UI.lua, never abandon frames

## NAMING CONVENTIONS
- Module files: PascalCase (`AutoEquip.lua`, `GearSets.lua`)
- Data files: PascalCase with underscores for compounds (`Professions_Data.lua`)
- Guide files: `TAG_ZoneName.lua` prefix
- Variables: camelCase (`currentSpecID`, `stepIdx`)
- Constants: UPPER_SNAKE (`MAX_LOG_SIZE`, `UPDATE_HZ`)
- WoW API wrappers: match WoW naming (`IsInInstance`, `GetPlayerFacing`)

## ERROR HANDLING
- All module Init: wrapped in `pcall` by Init.lua
- All module OnEvent: wrapped in `pcall` by Init.lua
- Errors logged to: `TA.ErrorLog:Log(source, msg, stack)`
- Max 200 errors retained in SavedVariables
- View with: `/ta errors`

## SAVEDVARIABLES PATTERN
- Global: `ToonAgeDB` (account-wide)
- Per-char: `ToonAgeDB.char["Name-Server"]` (accessed via `TA.charDB`)
- Always deep-default new keys (see Init.lua's DB_DEFAULTS pattern)
- Never wipe user data on version upgrade — backfill missing keys only

## UI CONVENTIONS
- Main frame: 900x580, sidebar 210px
- Typography: FRIZQT__.TTF (sans-serif), sizes 8-14pt
- Colors: warm-neutral palette defined in UIModern.lua
- Backdrops: flat 1px borders, translucent dark backgrounds
- Two layout modes: Unified HUD (default) and Fragmented Windows
- All UI frames: draggable, position saved in SavedVariables
- Scrollable content: use RebuildChild pattern from UI.lua

## ADDING A NEW MODULE
1. Create `Modules/NewModule.lua`
2. Start with: `local TA = ToonAge; local U = TA.Utils; local M = {}; TA:RegisterModule("NewModule", M)`
3. Add `function M:Init()` for setup on login
4. Add `function M:OnEvent(event, ...)` for event handling
5. Add to `ToonAge.toc` in the Modules section
6. If toggleable: add to `DB_DEFAULTS.modules` in Init.lua
7. If it has a tab: add to `TABS` array in UI.lua

## ADDING GUIDE CONTENT
1. Create `Data/Guides/TAG_ZoneName.lua`
2. Use schema: `TA.GuideData["zone_id"] = { id, title, zone, minLevel, maxLevel, steps={...} }`
3. Add to `ToonAge.toc` in the Data\Guides section
4. Steps need: type, text, questID (if quest), coord={map, x, y}
5. Test with `/ta guides` and `/ta autoselect`

## BLIZZARD API USAGE (EXTERNAL — Dev Tools Only)
- Register app at: **https://develop.battle.net/** → API Access → Create Client.
  (This file used to say `community.developer.battle.net`. That's the developer
  *forum*, not the app portal.) Redirect URI can be `https://localhost` — the
  client-credentials flow never redirects.
- Credentials live in `BLIZZARD_CLIENT_ID` / `BLIZZARD_CLIENT_SECRET` env vars,
  never in the repo. Set at User scope so they survive a reboot; a shell that is
  already open keeps the environment it started with.
- **Set them with `.\Tools\setup_credentials.ps1`** — prompts (secret hidden via
  `-AsSecureString`, so it never reaches scrollback or PSReadLine history),
  stores at User scope, and verifies immediately. `-Scope Process` for a
  throwaway pair, `-NoVerify` to skip the network check.
- **Check them with `python Tools/check_credentials.py`** before blaming a
  fetch script. It verifies auth *and* one real gateway call in two seconds,
  and never prints the credentials. Exit 0 = working, 1 = unset, 2 = rejected.
- Neither script ever prints the secret; the client ID is masked to first/last
  four so two clients can be told apart. Don't paste either value into a chat,
  a commit, or an issue.
- `/data/wow/quest/{id}` — the endpoint `fetch_wow_quests.py` uses — returns
  title, description, area, requirements and rewards, with **no x/y**. So the
  quest endpoint cannot close the guide coordinate gap; that's `/coord` walking
  or a licensing exception. Scope of this claim: that one endpoint, checked
  2026-07-26. The journal and map endpoint families have *not* been examined
  and are not covered by it.
- Auth: OAuth 2.0 Client Credentials Flow (game data)
- Auth: OAuth 2.0 Authorization Code Flow (player profiles — needs user consent)
- Gateway: {region}.api.blizzard.com (us/eu/kr/tw/cn)
- Always include: `namespace=` parameter (static/dynamic/profile)
- Output: baked into static Lua data files, committed to repo. **Destinations
  come from `Tools/paths.py`** (`DATA_DIR`, `GUIDES_DIR`, `QUESTS_CSV`) — never
  hardcode one. Three scripts used to point at a personal Desktop folder, which
  put generated data outside the repo and made the location machine-specific.
  Run `python Tools/paths.py` to print what everything resolves to.
- `crawl_wowdb_quests.py` was **deleted** 2026-07-26. It parsed a bulk-downloaded
  WoWDB HTML dump; `fetch_wow_quests.py` produces the same two files from
  Blizzard's licensed API and its own docstring already declared it the
  replacement. Don't reintroduce scraping of third-party database sites — the
  quest facts themselves aren't copyrightable, but bulk-downloading someone
  else's site is a terms-of-service question the addon licensing rules in
  `.bootstrap.md` don't cover.

## PERFORMANCE RULES
- Never scan all bags/inventory on every frame — use event-driven updates
- Throttle updates: 0.1-0.2s for combat, 0.5-1s for non-combat displays
- Debounce high-frequency events (QUEST_LOG_UPDATE → 0.15s coalesce)
- Frame pool: reuse, never abandon (WoW doesn't GC unparented frames)
- Max 30fps for NavHud/Arrow ticker (UPDATE_HZ = 1/30)
- pcall wrappers: catch errors without crashing the addon
