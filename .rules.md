# ToonAge — Development Rules & Style Guide
# Reference this file for coding standards and conventions.

## LUA STYLE
- Local references: `local TA = ToonAge; local U = TA.Utils`
- Module pattern: `local M = {}; TA:RegisterModule("Name", M)`
- Every module MUST have: `Init()` (optional), `OnEvent(event, ...)` (optional), `Render(content, sidebar)` (for UI tabs)
- Use `pcall` for any Blizzard API call that might taint or error
- Use `U.SafeNum(val)` for any potentially tainted number from WoW API
- File-scope constants: ALL_CAPS with underscores
- Comments: `-- Single line` for inline, `-- ══════` section separators for major blocks
- Clean up frames: every Render() must hide/nil old frames before creating new ones
- Frame pool: reuse frames via the pool pattern in UI.lua, never abandon frames

## NAMING CONVENTIONS
- Module files: PascalCase (`AutoEquip.lua`, `GearSets.lua`)
- Data files: PascalCase with underscores for compounds (`Professions_Data.lua`)
- Guide files: `TAG_ZoneName.lua` prefix
- Variables: camelCase (`currentSpecID`, `stepIdx`)
- Constants: UPPER_SNAKE (`MAX_LOG_SIZE`, `UPDATE_HZ`)
- WoW API wrappers: match WoW naming (`IsInInstance`, `GetPlayerFacing`)

## ERROR HANDLING
- All module Init: wrapped in `pcall` by Init.lua
- All module OnEvent: wrapped in `pcall` by Init.lua
- Errors logged to: `TA.ErrorLog:Log(source, msg, stack)`
- Max 200 errors retained in SavedVariables
- View with: `/ta errors`

## SAVEDVARIABLES PATTERN
- Global: `ToonAgeDB` (account-wide)
- Per-char: `ToonAgeDB.char["Name-Server"]` (accessed via `TA.charDB`)
- Always deep-default new keys (see Init.lua's DB_DEFAULTS pattern)
- Never wipe user data on version upgrade — backfill missing keys only

## UI CONVENTIONS
- Main frame: 900x580, sidebar 210px
- Typography: FRIZQT__.TTF (sans-serif), sizes defined in UIModern.lua:
  - H1: 14pt, H2: 12pt, H3: 11pt, Body: 10pt, Caption: 9pt, Tiny: 8pt
- Colors: warm-neutral palette defined in UIModern.lua:
  - Primary text: { 0.92, 0.90, 0.87 } — warm white
  - Secondary text: { 0.62, 0.59, 0.55 } — muted gray
  - Accent: { 0.40, 0.75, 1.00 } — cool blue
  - Success: { 0.30, 0.92, 0.40 } — green (done/upgrade/positive)
  - Warning: { 1.00, 0.65, 0.20 } — orange (attention needed)
  - Danger: { 1.00, 0.35, 0.30 } — red (error/critical)
  - Section headers: gold { 1.00, 0.82, 0.00 }
- Padding: 14px side (PAD), 8px between rows (RPAD)
- Backdrops: flat 1px borders, translucent dark backgrounds
- Styles: "panel", "card", "input", "header", "success", "danger", "warning"
- Two layout modes: Unified HUD (default) and Fragmented Windows
- All UI frames: draggable, position saved in SavedVariables
- Scrollable content: use RebuildChild pattern from UI.lua

## UI COMPONENT FACTORY (Phase 3 — use in all new code)
- Prefer `TA.Modern:SectionHeader(parent, y, w, title)` over hand-rolled headers
- Prefer `TA.Modern:DataRow(parent, y, w, {label, value, status})` over custom rows
- Prefer `TA.Modern:InfoCard(parent, y, w, {height, style})` over manual card frames
- Prefer `TA.Modern:ProgressBar(parent, y, w, {label, current, max, color})` over custom bars
- Prefer `TA.Modern:ActionButton(parent, y, w, {text, onClick, style})` over raw buttons
- Prefer `TA.Modern:Divider(parent, y, w)` over hand-drawn separator textures
- Prefer `TA.Modern:Spacer(y, amount)` over `y = y - 8` scattered throughout
- Prefer `TA.Modern:EmptyState(parent, text)` for blank/no-data states
- Prefer `TA.Modern:Badge(parent, text, color)` for inline status tags
- Prefer `TA.Modern:CreateCollapsibleSection(parent, opts)` for accordion sections
- All components return (frame, newY) or just newY for proper layout chaining
- Hover feedback on interactive elements is built into ActionButton and DataRow
- Status colors propagate through the `status` field, never hardcode RGB inline

## ADDING A NEW MODULE
1. Create `Modules/<Domain>/NewModule.lua` in the appropriate subdirectory:
   - `Navigation/` — guide engine, waypoints, arrows, map overlays
   - `Combat/` — rotation, combat state, pull planning, spec adaptation
   - `Gear/` — equipment scoring, auto-equip, tooltips, dungeon loot
   - `Character/` — identity, talents, professions, collections
   - `Progression/` — endgame tracking, alts, dungeons, weekly vault
   - `Farming/` — gathering, farm routes, profession questing
   - `Automation/` — quality-of-life auto-features, mounts, cutscenes
   - `Infrastructure/` — settings, errors, dev tools, onboarding
2. Start with: `local TA = ToonAge; local U = TA.Utils; local M = {}; TA:RegisterModule("NewModule", M)`
3. Add `function M:Init()` for setup on login
4. Add `function M:OnEvent(event, ...)` for event handling
5. Add to `ToonAge.toc` in the matching `# ── Modules: <Domain>` section
6. If toggleable: add to `DB_DEFAULTS.modules` in Init.lua
7. If it has a tab: add to `TABS` array in UI.lua

## CHECKING YOUR WORK BEFORE A RELOAD
There is no Lua interpreter on the PATH, so both of these run through Python.
- `python Tools/check_lua.py` — parses every file in the TOC. Syntax only:
  unbalanced `end`, missing `then`, a stray brace after an edit. Catches the
  class of mistake that is otherwise invisible outside the game.
- `python Tools/test_onboarding.py` — **executes** Core/Init.lua and
  Modules/Onboarding.lua in embedded Lua 5.1 (the version WoW runs) against a
  stub API, and asserts on behaviour. Needs `pip install --user lupa`.
  Pattern worth copying for other modules: fresh runtime per scenario, a
  virtual clock so `C_Timer.After` callbacks can be driven deterministically,
  and fakes for collaborating modules rather than loading the real files.
- Neither replaces a `/reload`. They prove the code parses and decides
  correctly; they say nothing about real frames, actual visibility, or
  SavedVariables surviving a session.
- A suite that has never been seen to fail is not evidence. Mutate the fix back
  out, confirm the tests go red, restore.

## ADDING GUIDE CONTENT
1. Create `Data/Guides/TAG_ZoneName.lua`
2. Use schema: `TA.GuideData["zone_id"] = { id, title, zone, minLevel, maxLevel, steps={...} }`
3. Add to `ToonAge.toc` in the Data\Guides section
4. Steps need: type, text, questID (if quest), coord={map, x, y}
5. Test with `/ta guides` and `/ta autoselect`

## BLIZZARD API USAGE (IN-GAME)
# Verified by live /dump on 12.1.0 (Midnight PTR), 2026-07-26. Anything added
# here without a dump behind it is a guess — mark it as such or leave it out.
- Quest: C_QuestLog
- Map: C_Map
- Gear: GetInventoryItemLink, GetItemInfo, C_Item
- **`C_Item.GetItemInfo` is an exact mirror of the global `GetItemInfo`** —
  verified 2026-07-26 by comparing all returns for one item: both give 18
  values and every position matches. So `U.GetItemInfo`, which prefers
  `C_Item.GetItemInfo` and falls back to the global, is safe for positional
  destructuring, and TODO #17's migration of the remaining bare calls is safe
  to continue. Re-check with:
  ```
  /run local a={GetItemInfo(6948)} local b={C_Item.GetItemInfo(6948)} print("counts:",#a,#b) for i=1,math.max(#a,#b) do if tostring(a[i])~=tostring(b[i]) then print(i,tostring(a[i]),"VS",tostring(b[i])) end end
  ```
  This mattered because three call sites read by position (`Utils.lua:276` takes
  return 4 as ilvl, `Utils.lua:282` takes return 3 as quality, `Gear.lua:209`
  takes 9/12/13), and a tuple mismatch there would have produced wrong values
  with no error — the same silent-failure shape as `C_Navigation.GetDestination`.
- Talents: C_Traits, C_ClassTalents
- Weekly: C_WeeklyRewards
- Professions: C_TradeSkillUI, C_ProfSpecs
- Pets: C_PetJournal
- Mounts: C_MountJournal
- Reputation: C_Reputation, C_MajorFactions
- AH: C_AuctionHouse (requires auctioneer proximity)
- Comms: C_ChatInfo.SendAddonMessage (party sync)
- Instance: IsInInstance, GetInstanceInfo
- Navigation: C_SuperTrack, and C_Navigation *only* for the on-screen arrow
  (GetFrame / GetDistance / GetTargetState / HasValidScreenPosition /
  WasClampedToScreen / GetNearestPartyMemberToken / GetNextWaypointForMap)

## REMOVED IN 12.1.0 — DO NOT USE (verified nil by live dump 2026-07-26)
- `C_Navigation.GetDestination` — gone. Was the only coord source in
  CoordResolver's QuerySuperTrack, guarded by `if C_Navigation.GetDestination`,
  so its removal failed *silently* rather than erroring.
- `C_QuestObjectiveTracker` — the whole namespace is nil. Never referenced in
  ToonAge code; it was only ever an aspirational entry in this file.
- Unconfirmed: whether `C_QuestLog.GetNextWaypointForMap` / `GetNextWaypoint`
  survive, and the signature of the new `C_Navigation.GetNextWaypointForMap`.
  To settle both, supertrack a quest and dump these — check the first one first,
  because `C_QuestLog.GetNextWaypointForMap` is the one that takes a questID, and
  if it survived then the `C_Navigation` signature question is moot:
  ```
  /dump C_QuestLog.GetNextWaypointForMap(C_SuperTrack.GetSuperTrackedQuestID(), C_Map.GetBestMapForUnit("player"))
  /dump C_QuestLog.GetNextWaypoint(C_SuperTrack.GetSuperTrackedQuestID())
  /run print(pcall(C_Navigation.GetNextWaypointForMap, C_Map.GetBestMapForUnit("player")))
  ```
  (An earlier revision of this file told you to run `/taapiprobe`. No such command
  exists — it was never built. Don't re-add a pointer to it without the code.)

## BLIZZARD API USAGE (EXTERNAL — Dev Tools Only)
- Register app at: **https://develop.battle.net/** → API Access → Create Client.
  (This file used to say `community.developer.battle.net`. That's the developer
  *forum*, not the app portal.) Redirect URI can be `https://localhost` — the
  client-credentials flow never redirects.
- Credentials live in `BLIZZARD_CLIENT_ID` / `BLIZZARD_CLIENT_SECRET` env vars,
  never in the repo. Set at User scope so they survive a reboot; a shell that is
  already open keeps the environment it started with.
- **Set them with `.\Tools\setup_credentials.ps1`** — prompts (secret hidden via
  `-AsSecureString`, so it never reaches scrollback or PSReadLine history),
  stores at User scope, and verifies immediately. `-Scope Process` for a
  throwaway pair, `-NoVerify` to skip the network check.
- **Check them with `python Tools/check_credentials.py`** before blaming a
  fetch script. It verifies auth *and* one real gateway call in two seconds,
  and never prints the credentials. Exit 0 = working, 1 = unset, 2 = rejected.
- Neither script ever prints the secret; the client ID is masked to first/last
  four so two clients can be told apart. Don't paste either value into a chat,
  a commit, or an issue.
- `/data/wow/quest/{id}` — the endpoint `fetch_wow_quests.py` uses — returns
  title, description, area, requirements and rewards, with **no x/y**. So the
  quest endpoint cannot close the guide coordinate gap; that's `/coord` walking
  or a licensing exception. Scope of this claim: that one endpoint, checked
  2026-07-26. The journal and map endpoint families have *not* been examined
  and are not covered by it.
- Auth: OAuth 2.0 Client Credentials Flow (game data)
- Auth: OAuth 2.0 Authorization Code Flow (player profiles — needs user consent)
- Gateway: {region}.api.blizzard.com (us/eu/kr/tw/cn)
- Always include: `namespace=` parameter (static/dynamic/profile)
- Output: baked into static Lua data files, committed to repo. **Destinations
  come from `Tools/paths.py`** (`DATA_DIR`, `GUIDES_DIR`, `QUESTS_CSV`) — never
  hardcode one. Three scripts used to point at a personal Desktop folder, which
  put generated data outside the repo and made the location machine-specific.
  Run `python Tools/paths.py` to print what everything resolves to.
- `crawl_wowdb_quests.py` was **deleted** 2026-07-26. It parsed a bulk-downloaded
  WoWDB HTML dump; `fetch_wow_quests.py` produces the same two files from
  Blizzard's licensed API and its own docstring already declared it the
  replacement. Don't reintroduce scraping of third-party database sites — the
  quest facts themselves aren't copyrightable, but bulk-downloading someone
  else's site is a terms-of-service question the addon licensing rules in
  `.bootstrap.md` don't cover.

## PERFORMANCE RULES
- Never scan all bags/inventory on every frame — use event-driven updates
- Throttle updates: 0.1-0.2s for combat, 0.5-1s for non-combat displays
- Debounce high-frequency events (QUEST_LOG_UPDATE → 0.15s coalesce)
- Frame pool: reuse, never abandon (WoW doesn't GC unparented frames)
- Max 30fps for NavHud/Arrow ticker (UPDATE_HZ = 1/30)
- pcall wrappers: catch errors without crashing the addon
